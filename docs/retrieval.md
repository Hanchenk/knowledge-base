# 检索与月度报表问答

## 参考实现

本轮阅读了本机 `yemast-wiki`（PandaWiki）的 `backend/store/rag/ct.go`、`backend/usecase/llm.go` 和 `sdk/rag/models.go`。它的业务后端把检索交给独立 raglite 服务，将问题、历史消息、权限元数据、相似度阈值和每文档片段数传入，接收重写问题与相关片段，再按文档归组展示来源。SDK 还声明了文档 ID 过滤、向量权重、RerankID、Excel 表格解析和文件名向量权重等参数；这些声明不代表该仓库已经启用了所有功能，底层检索算法不在业务仓库内。

当前项目借鉴文档范围、标题上下文、保留表格结构和按文档组织证据的思路，继续使用 Rust 业务与检索后端，不引入该项目的 Go 服务。本轮新增的是确定性证据重排，未接入外部神经 reranker 或模型问题重写。

## 查询流程

1. 校验租户、账号/API Key scope 和空间查看权限。
2. 识别显式年月、ISO 日期或中文月日；以文档标题和文件名限定报告范围。有明确报告匹配时结合标题关键词排除无关文档；没有足够标题信号时仍保留未标日期的资料。
3. 表格片段使用解析器生成的工作表日期限定范围，事故备注里的其他日期不会改变报告归属。先过滤，再做关键词和向量召回，避免候选额度被错日期数据耗尽。
4. PostgreSQL 全文检索/SQLite BM25 和向量余弦相似度各召回最多 64 个片段，再做 RRF 融合。
5. 根据标题匹配和月度汇总意图做规则重排；月度汇总还直接召回索引时生成的整月快照，不依赖少量随机数据行覆盖所有场站。
6. 默认最多 6 个结果、每文档最多 3 个片段，再次检查当前权限。生成回答后重新检查权限及文档版本。

日期识别支持显式月份、年份、`2025-11-30` / `2025/11/30` / `2025年11月30日` / `11月30日`。未指定年份时不会默认猜测年份，同月不同年份均可能进入结果。暂未实现“上个月”等相对日期解析和复杂日期区间语义。

## XLSX 解析与口径

- XLSX 读取缓存公式结果，不运行公式。解析合并表头、连续多行表头、单位和同一工作表内的多段表区。
- 每条数据行携带标题、工作表名称、报告日期、表区和原始行号；表格行不再按 900 字符硬切。独立表头已包含于数据行，不重复索引成高排名的空数据片段。纯文字表和无表头表仍保留原始行。
- 百分比按 Excel 格式或明确的百分比单位转为百分数。缺失值和 `/` 保留，不转成零；空白行和 WPS 保留图片清单不进入索引。
- 向量输入包含文档标题及片段内容。调整解析后必须重新索引原文件；本地已有 8 份 XLSX 已通过授权重建索引，无需重复上传。
- 显式日报日期和月度电量字段构成月累计快照。逐场站读取当月最后一份可用日报里的月发电量、月供电量、预算、完成率及结算电量，同时标明截至日期、逐日记录覆盖天数和来源工作表/行。
- **不把每天的月累计相加，不把合计与分站重复累加**。原表中的名称差异不会自动合并；同站同日期出现重复行时不把不明确的末日数据写进快照。屋顶光伏等独立表区保留为独立项目。
- 截至月末的累计快照可以使用，逐日明细覆盖不全不能解读为累计值不存在。只有较早日期的场站需按其截至日期说明，不能冒充完整月末值。

这是明确字段和日期条件下的月度快照整理，尚非通用 Excel 计算引擎：不会执行任意公式，不从缺失累计字段中推算，也不对不明确的同名场站做跨文件实体合并。非标准表头或单位仍需查看解析结果核对。

## 页面显示与边界

问答与文档详情使用 GFM 渲染真实表格，宽表在容器内横向滚动。详情将 `table_summary` 标为“月累计汇总”，其来源行号和工作表在表内可核对。问答模型接收月度口径提示并可输出完整场站表；输出仍需以引用原文为准。

表格单条最多 24,000 字符、单文档最多 4,000 个片段，过限明确失败，不静默截断。SQLite 仍是最多 20,000 个授权片段的开发模式；大型部署使用 PostgreSQL。结果数量限制仍适用，多文档年度/跨月完整统计应明确范围并检查引用是否覆盖全部所需文档。
