# 知小汇 Agent 记忆与经验接入

按个人跨任务记忆 → 审核后的技能沉淀 → Wiki / CodeGraph 顺序接入，三个模块在「账号菜单 → 个人中心 → 管理记忆与经验」统一管理。个人中心提供跨任务记忆、提取任务经验与技能提炼三个独立开关，保存到当前账号；对话页不再显示记忆管理及完成任务的提炼按钮。Pi Core、官方 DeepSeek Harness 和授权本地工具桥使用同一组 Rust 平台工具。

## 个人跨任务记忆

用户可手动添加偏好、约定和经验，直接生效；Agent 的 `memory_propose` 只创建待审核草稿。来源任务完成且其资料仍可访问时，用户可审核确认。`memory_search` 和新任务启动时只召回本账号已确认、来源仍有效的记忆，最多 5 条 / 4,000 字；每条最多 2,000 字，每人最多 100 条。

个人设置分别控制跨任务召回与 Agent 提议；任务的 `options.memory_enabled` 可单独关闭这两个工具。记忆正文以租户密钥加密保存，浏览器管理接口拒绝 API Key。系统覆盖模型传入的身份，不接受客户端指定租户、用户或上游路径。

未配置 MemoryCore 时采用明确标注的本地关键词召回。配置后 worker 通过实际 `/v3/core/write`、`/v3/core/read` 同步每人的审核快照，Core 的 agent_id 与 tenant+user 唯一绑定。平台仍是审批和权限的依据。该版本没有导出所有任务对话，也不启用不可追踪来源的 L1/L2 自动画像。腾讯 Core 在这里承担可控的持久化后端；召回排序仍是平台关键词规则。

删除和「忘记全部」会清空平台记忆正文并排队替换 Core 当前快照；忘记全部还关闭 Agent 提议。上游故障时本地立即停止召回，后台重试清理，界面显示同步错误。原始任务对话仍保留，腾讯服务自行保存的文件历史 / 备份需按部署保留策略清理；快照覆盖不宣称物理擦除全部备份。worker 定期重新检查来源权限和内容变化，剔除失效来源。

## 审核后的技能沉淀

从已完成的本人任务提炼流程。配置腾讯 Core 时使用真正的异步 `/v3/skill/extract`，仅导入精确关联 task_id 的结果；未配置 Core 时调用租户已配置的问答模型。用户也可手动填写草稿，Agent 的 `skill_propose` 同样只能提议。

个人中心的「技能提炼」开关独立于记忆召回和候选记忆采集。关闭后，浏览器与 Agent 均不能提交新的技能候选，既有提炼请求继续处理，已有候选仍可审核、撤回或删除。开关控制提炼权限，不会自动遍历或批量提炼历史任务。设置接口支持部分字段更新，未提交的设置保留原值。

腾讯技能目录要求真实注册的用户、团队与 Agent。平台为每个租户内的用户分别注册普通原生用户及私人 Agent，原生 owner key 加密保存，注册映射同时绑定服务地址和实例。管理员引导密钥仅供后端注册使用，不进入浏览器或任务进程。个人记忆快照继续使用原有确定性身份，技能注册不会改变已有记忆归属。

候选草稿采用租户加密存储，绑定来源任务、引用版本、内容指纹和技能依赖。审核使用版本比较，正在提炼、来源变更、撤权或过期的草稿不能通过。审核通过后转换为平台私有 `bot_skills` 工作流文本；不安装上游附带文件、npm 资源或执行入口。仅在用户选择时交给模型，不能扩张联网、连接器、代码或其他工具权限。

删除候选技能会事务性撤销其可选技能，并排队重试腾讯技能清理。未完成的远程提炼会保留清理回执，后续产生的同一任务结果也会删除。腾讯提炼服务内部可先产生 active 结果，但平台严格以自己的审核状态决定可用性。

远程提炼前先持久化候选和调用记录。若请求已发出但响应丢失，平台将候选标记为失败并保留原生身份、服务命名空间及 session 回执，暂停自动重发。上游目前没有按 session 反查提炼任务的公开接口，这类记录需要运维核对，不宣称已自动清理未知的远程结果。已收到真实任务回执的请求仍按原有清理队列处理。

## Wiki 与 CodeGraph

Wiki 绑定 1–20 份可读、已解析的文档，以当前索引版本上传；CodeGraph 首期限定公开 HTTPS GitHub 仓库，服务端核对真实公开性与默认分支。构建、同步、失败和删除状态持久化。后台接入实际 MemoryKnowledge API；未配置时拒绝创建，不返回伪造索引或检索结果。

任务以 `options.knowledge_asset_ids` 显式选择资产，工具限制到所选资产：`wiki_search`、`wiki_read`、`code_graph_search`、`code_graph_callers`、`code_graph_callees`、`code_graph_impact`、`code_graph_read`。所有上游请求注入平台身份，Wiki 检索前后均检查文档权限与版本，Wiki 来源进入现有任务引用体系。部署细节与只读工具参数见 [Wiki / CodeGraph 接入](wiki-codegraph-integration.md)。

## 恢复和来源失效

每次使用个人记忆或知识资产会保存任务来源回执。检查点恢复、缓存工具结果复用、后续对话、技能提炼以及成果读取都重新核验来源；删除、修改、撤权或技能撤销后，受影响任务的成果隐藏，不能借旧检查点继续使用失效内容。用户可新建任务使用当前授权资料。

现有当前任务 `task_memory`、`runtime_recall` 和检查点继续承担执行恢复，不被长期记忆替换。记忆与 Wiki/代码索引的结果始终是不可信数据，不能改变任务工具授权。

## 环境与验收

服务配置：`MEMORY_CORE_URL` + `MEMORY_CORE_TOKEN`、`MEMORY_KNOWLEDGE_URL` + `MEMORY_KNOWLEDGE_TOKEN`；`MEMORY_SERVICE_ID` 默认 `zhixiaohui`。真实 Core 技能提炼还需配置 `MEMORY_CORE_ADMIN_USER_KEY`，对应经 `/v3/meta/user/init-admin` 初始化并核验的本实例管理员密钥。URL 只由部署配置提供，访问令牌不进入浏览器、Harness 配置或插件环境。API 和 worker 均需配置；后台 worker 负责记忆同步、技能清理与知识构建。

可选容器入口：`deploy/compose.tencent-memory.yaml`；基于调研固定上游提交 `274e549069ad780e411d70e6fff51f6a977d81d3`。需要另外提供模型服务设置；不会复用或泄露用户的任务 API Key。

自动化验收包括临时 SQLite 数据库的隔离、审批、来源撤权、工具回执和服务故障重试，HTTP fixture 核对真实上游路径、身份和业务响应，浏览器 fixture 测试界面与选项流转。HTTP / UI fixture 测试不能替代部署后的真实模型生成质量、真实仓库索引性能和腾讯服务现场验收。部署后应按三阶段分别验证新增、任务召回 / 选用、删除与权限撤销，再逐步启用。


初次本地验收记录见 [验证记录](agent-memory-integration-verification.json)：后端全套 91 项与补充 1 项 Core 对账回归、53 项运行时测试、9 项新增浏览器测试、3 项既有浏览器回归、9 项资料解析测试、生产构建、Rust 格式与 Clippy 均通过，浏览器及上游 HTTP 使用 fixture。随后在生产服务器的独立合成身份下完成真实 Core 读写、私人技能提取、Wiki 建索引与 CodeGraph 真实仓库查询；最新镜像、PostgreSQL 迁移及生产切换结果单独记录于 [生产发布记录](agent-memory-production-deployment.md)。前端本次功能文件格式检查通过；全库 Prettier 检查仍在未改动的 11 个 `src/vendor/bloub/*.ts` 文件报告既有格式问题。
