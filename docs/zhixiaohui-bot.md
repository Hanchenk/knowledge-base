# 知小汇 bot：产品规划与实现

目标是把截图中的六类能力整合为平台内的个人工作助手：用户交办任务，bot 检索授权资料、规划步骤、调用工具、保存成果，用户可以随时换设备查看进度或继续对话。

| 截图能力 | 平台落地 | 使用入口 |
| --- | --- | --- |
| 前沿模型 | 复用企业问答模型与 Pi Agent；模型、联网、代码按实际配置启用 | 模型设置、任务输入栏 |
| 强大的任务执行 | 持久任务队列、步骤更新、工具调用记录、取消、重试、可核验成果、上一轮对话上下文 | 任务工作台 |
| 丰富的连接器生态 | 用户私有的固定 GET / POST API；Bearer 凭据加密，选定连接器才可调用，POST 展示准确请求后确认 | 输入栏 → 应用连接器 |
| 可靠的云端电脑 | 后台 Worker、公开网页搜索与正文读取、授权文件读取、私有成果文件、无网络 Python 容器 | 输入栏 → 云端 |
| 跨设备协作 | 服务器持久化；同一账号的电脑 / 手机可恢复任务、确认操作、下载成果和继续对话；页面隐藏时停止轮询 | `/app?view=bot&task=<id>` |
| 社区技能 | 四个内置工作流：研究、会议、分析、写作；创建或导入 Markdown / SKILL.md；任务保存技能快照 | 输入栏 → 技能 |

## 交互流程

1. 输入 1–6000 字的任务，通过输入栏内的「资料」「应用连接器」「技能」面板搜索、多选；最多选择 10 份已索引资料、5 个技能、10 个连接器。已选项显示为可移除标签。
2. 在输入栏「云端」面板按需打开联网搜索和代码执行；不可用的工具会禁用。未选择资料时搜索当前授权知识空间。支持 ⌘ / Ctrl + Enter 提交，Esc 关闭选择面板。
3. Pi 使用知识工具、公开网页工具、`task_plan`、`read_artifact`、`write_artifact`、`run_python` 和选定的 `connector_call`。模型的公开回复逐步显示在左侧对话中；步骤、工具记录和较早的工作说明默认收在「执行过程」中，展开后在限高区域内滚动，不展示内部推理。
4. 读取连接器立即返回数据；写入连接器先持久化准确 URL、方法、JSON 请求，任务进入等待确认状态。确认后发出实际请求，并把真实响应交给 bot 继续处理。
5. 完成后可以下载成果；继续对话会创建引用上一轮任务的新任务，默认保留资料和工具选择，也可在继续对话的输入栏内调整，并可分页读取上一轮成果后修改。上一轮资料失效时不能继续使用旧上下文。

未配置 Agent 时，任务交付真实原文检索报告，明确标为原文检索模式。不会模拟智能分析或外部操作。

页面采用左侧连续对话、右侧 bot 工作区的布局，使用浅灰蓝对话背景和蓝色到浅桃色的工作区渐变。输入栏固定在对话区底部；对话和工作区分别滚动。右侧随时收起或展开，记住用户的选择，收起后任务与流式输出继续运行。工作区提供成果、资料引用和文件下载；手机端默认显示对话，工作区通过覆盖面板展开。任务历史在标题栏弹出，继续对话时恢复前面各轮内容。

组件使用统一的入场、聚焦光流、选择面板与标签过渡，角色轨道缓慢流动，生成中的文字带轻微脉动光标；系统开启减少动态效果后，全部页面动效停止。对话滚动只在用户停留于底部时自动跟随，手动阅读旧内容时可通过「回到最新」继续跟随。

系统侧边栏边缘提供胶囊形拖动把手：向左拖动收起，向右拖动展开，也可点击切换，方向键控制收放。拖动时侧边栏与内容区同步跟随，松手后平滑归位，Esc 或触摸取消会恢复原状态；悬停有轻微光晕与方向提示。桌面收起状态本地保存，隐藏导航从键盘访问中移除；手机通过覆盖面板展开，支持真实触摸拖动，页面内容保持原位。收放导航不会重新加载对话或中断 SSE。

## 流式输出与恢复

Node runtime 订阅 Pi 的 assistant 文本事件，只转发公开文字，不转发 thinking 块或工具参数。首个文本增量立即发送，后续最多每 100ms 合并一次；Rust 检查当前身份、任务租约和资料授权后保存到迁移 `007_bot_messages.sql` 的消息表。

`GET /api/bot/tasks/{id}/stream` 通过 SSE 返回初始 `snapshot`、随后 `output` 文本增量和结束状态。服务每 250ms 检查数据库中的变化；客户端断线后重新连接并恢复快照，刷新页面也会恢复已生成内容。页面隐藏时暂停连接，回到页面重新连接；连接不可用时仍通过三秒轮询同步。模型未输出公开文字时显示正在准备回复，不使用模拟打字。

SSE 和消息写入沿用任务的私有访问与资料授权规则。取消后旧租约不能再保存文字；资料更新或撤权后隐藏输出、历史对话和成果，并结束连接。待确认的外部操作完整请求始终单独显示，方便用户审阅。

`BloubAvatar.tsx` 将原 Vue SVG 渲染器适配为 React，保留形状、眼睛、粒子和轨道参数。只调整了可选自定义形状校准表的计算时机，让未使用的形状无需在页面加载时计算。

| --- | --- |
| 待命 | idle，眨眼与视线漂移 |
| 输入任务 | idle + attentif，专注表情 |
| 提交 / 排队 | thinking，三点脉动 |
| 执行中 | orbit 与 thinking 平滑切换 |

## 连接应用

部署配置使用精确的 `host:port` 白名单，例如：

```dotenv
BOT_CONNECTOR_HOSTS=api.github.com:443,graph.microsoft.com:443,www.googleapis.com:443,open.feishu.cn:443
```

从输入栏「应用连接器 → 管理连接器」填写固定 API 地址、名称、参数说明、GET / POST 和可选 Bearer Token。GET 把 `input` 转为查询参数；POST 把 `input` 原样作为 JSON，并发送 `Idempotency-Key`。描述应说明 API 所需字段。例如 GitHub issue 写入连接器可固定到 `https://api.github.com/repos/OWNER/REPO/issues`，描述注明 `title`、`body` 的含义。

第三方应用必须有可调用的 API 或企业桥接服务及有效凭据。当前没有预置 OAuth 安装向导；飞书、钉钉、邮件、日历等需按实际接口配置。GET 用于只读接口；不要将具有写入副作用的 GET 接口配置成读取工具。POST 测试仅校验配置，不发送写入；真实读取测试会发出 GET。请求不跟随重定向、不使用代理，响应限制 256 KB，超时 20 秒。

外部请求只在用户点击具体操作的「确认执行」后发送。确认以原子状态更新避免重复点击；相同任务、连接器、JSON 请求去重。超时、进程中断和不确定响应不会自动重发，页面保留待核实记录，用户应在外部系统核对。

## 隔离 Python

本机部署：

```bash
docker pull python:3.12-alpine
```

```dotenv
BOT_CODE_ENABLED=true
BOT_CODE_IMAGE=python:3.12-alpine
```

API / Worker 需要能调用 Docker CLI。代码在一次性容器中执行：无网络、不挂载宿主目录、不传入应用环境变量、只读根目录、非 root、移除 capabilities、禁止新增权限、128 MB 内存、1 CPU、32 个进程、16 MB 临时目录、30 秒超时、每个输出流最多 128 KB。支持 Python 标准库；输出可以通过成果工具保存为文件。取消任务同时清理容器。镜像必须提前拉取，运行时不自动下载。

容器部署可以选择独立的 Docker daemon 覆盖配置：

```bash
docker compose -f compose.yaml -f compose.bot-code.yaml up -d --build
# 在专用 sandbox daemon 中准备代码镜像：
docker compose -f compose.yaml -f compose.bot-code.yaml exec sandbox docker pull python:3.12-alpine
```

覆盖配置使用 TLS 连接专用 `sandbox` 服务，证书包含 `DNS:sandbox`，并通过 daemon 健康检查控制启动顺序；不挂载生产宿主的 Docker socket。该可选 DinD 服务需要 privileged；部署环境应将它放在专用执行节点。代码容器本身不使用 privileged。启动后页面会检查 daemon 和镜像是否实际可用，再开放「代码」开关。

这里的云端空间提供网页正文读取、文件与隔离代码工具。它没有浏览器账号登录、鼠标键盘远程桌面、任意设备控制或 SLA 承诺。Worker / 基础服务必须持续运行，才能持续处理任务。

## 数据与权限

- 新迁移 `005_bot.sql` 支持 SQLite / PostgreSQL，创建任务、事件、成果、连接器、确认操作和技能表。
- 任务、文件、技能、连接器仅本人可访问，API Key 不能调用 bot 的浏览器专属接口。
- 凭据复用企业模型配置的 AES-256-GCM 加密密钥，API 不返回 Token 原值。
- 知识检索和读取复用现有 ACL；资料更新、删除或撤权后，结果、计划、事件、操作请求和成果下载整体隐藏。
- API 与独立 Worker 使用数据库原子领取与租约。执行中每两秒检测取消并续租；租约过期明确失败，避免崩溃后静默重复外部写入。
- 技能只导入工作流文本，不执行外部包内脚本，不扩大工具权限。任务保存导入时的技能快照。
- 同一 `request_id` 的重试返回原任务；不同内容使用相同 ID 会拒绝；同一用户最多 10 个未完成任务。任务列表返回最近 100 条。
- 成果支持 `.md`、`.txt`、`.csv`、`.json`、`.py`，最多 300 KB，按附件下载，避免执行用户生成的 HTML。

## 持续任务运行机制（2026-10-10）

底层仍使用 `@earendil-works/pi-agent-core@0.87.0`。`agent-runtime/harness.mjs` 接入 Pi 的 prepareRequest、afterToolCall、finishTurn 和异步生命周期监听；Rust 承担当前身份、工具权限、租约、成果与审批的校验。

- 删除 8 次模型请求、16 次工具调用的固定失败条件。bot 没有 250 秒全任务超时；bot 单次模型请求保留 300 秒期限，普通问答仍为 120 秒。bot 每 15 秒发送运行心跳并再次核对身份与租约，避免长报告生成被协议空闲误判。协议空闲期限为 180 秒，工具执行期限为 120 秒，Python 仍为 30 秒。
- `AGENT_CONTEXT_WINDOW=32768` 是保守默认容量，应按实际问答模型调整；`AGENT_MAX_OUTPUT_TOKENS=5000` 预留回答空间。UTF-8 字节量估算输入 token（除以 3），在可用输入预算的 80% 前压缩。完整 assistant/tool 批次一起保留或归档；不产生孤立 tool result。原始任务目标、当前系统规则始终保留，旧记录整理为明确标记的不可信摘要，另保存计划、文件 ID、来源编号/URL 和审批状态目录。过大的近期工具批次也会归档。
- 摘要调用使用当前租户模型；失败时使用注明缺失的历史摘录，不编造完成状态。工具原文存放在加密 journal 中，可用 `runtime_recall` 分页读取。服务返回 context overflow 时自动压缩并重试一次；能识别服务返回的实际容量，否则缩小预算；有效容量跟随检查点保存。
- 迁移 `006_bot_runtime.sql` 增加租户加密的运行检查点和工具 journal。每个模型请求前、assistant/tool 消息提交后，Node 等待 Rust 持久化确认。检查点不存 API Key，不恢复旧 system 消息/工具授权。恢复时重建当前工具目录，并再次检查用户状态、资料版本与权限。
- 工具执行使用模型 tool call ID 持久化开始与结果。崩溃后已提交的结果直接复用；已经开始却未保存结果的调用返回中断信息，禁止自动重放。连接器 POST 仍只生成待确认操作，保持精确载荷审批、指纹去重与不确定写入保护。
- 正常推进的任务每 `BOT_AGENT_SLICE_SECONDS=600` 秒在完整轮次结束后让出 Worker，自动重新排队并从检查点继续；按入队更新时间公平调度。Worker 租约失效、有检查点且没有不确定外部写入时自动恢复。无检查点的旧任务仍显示中断原因。
- 读工具缓存按规范化 URL、页码、文件范围识别重复，缓存返回已读证据摘录与原归档 call_id；新参数返回相同片段、重叠网页范围、空结果和历史 recall 也不会视为新证据。旧检查点从加密 journal 重建已读范围；缓存出示前仍经过 Rust 身份、租约、资料权限与版本检查。
- 连续 3 次读取没有新增证据时提示推进分析与交付，连续 8 次进入交付阶段，暂时收起取材工具，先保存当前证据范围内且注明未核实项的成果草稿，保存后恢复工具用于补证；纠偏后仍有 3 轮没有进展就保存并暂停。新证据、实际完成步骤或保存成果会重置状态；计划标题改写不算进展。这些阈值用于无进展检测，不限制正常工具调用总数。原有相同参数/结果重复检测继续保留。显式继续重置无进展状态并保留已读证据；取消立即使旧租约失效。
- 运行时自动保留有引用的原文摘录，即使模型没有调用笔记工具，摘录也会跨压缩和恢复保留。`task_memory` 保存模型整理的具体事实、引用、未核实项和下一步；它是历史数据，不能授予权限，也不代表系统替模型保证事实正确。持久目录优先保留事实，按上下文预算选取完整 JSON；完整笔记与原文在加密 journal 中可回读。摘要保留上一份事实摘要，区分工具截断、分页未读与压缩省略，避免把省略误认为来源未核验。
- `web_fetch` 默认返回 6000 个 Unicode 字符，`start` / `limit` 可分页（单页最多 12000）；返回 `total_chars`、`next_start` 和 `source_truncated`。正文最多提取 200000 字符，超过上限明确标记；保留原有公共地址、DNS 固定、跳转校验与原始响应 2 MB 限制。
- Worker 续租与任务执行作为两个持续轮询的 future 运行；续租等候检查点行锁时，任务仍能提交事务，避免 PostgreSQL 行锁与单个 select 分支形成死锁。暂停/失败/取消后的步骤不再显示执行动画。

验证覆盖 24 次连续工具调用、自动压缩、摘要失败回退、服务 context overflow、完整工具批次、90KB 文件参数归档、检查点恢复、崩溃后的成果复用、租约/取消/私有任务隔离和资料撤权。默认模型容量仍需要与实际服务匹配；模型服务自身的故障会显示失败并保留可恢复进度。


## 研究任务收敛修复

生产中一项“harness 工程”研究任务在取消前运行 20 分 12 秒，106 次工具调用、15 次压缩，0 个成果；多份相同资料各重读 13–14 次，计划仍在第一步。原因包括网页无分页、摘要反复丢失具体事实、已读目录缺少覆盖信息，以及轮流读取不同来源绕过单工具重复检测。先前长任务 fixture 证明持续执行和恢复，不能证明真实研究任务能收敛。

本次回归除真实 PostgreSQL / Qdrant / MinIO 的权限、取消与恢复测试外，增加轮换相同来源与计划改写、等价检索、失败/空读取、跨压缩事实、旧 journal 缓存重建、缓存前权限检查、Unicode 网页尾页与截断标记。PostgreSQL 测试通过延迟首次检查点强制与续租锁冲突。真实模型回放只使用原任务已取得的证据、独立生成测试成果，不恢复或修改已取消的生产任务；详细结果记录在 `bot-convergence-verification.json`。

成果目录和计划状态会作为短状态数据单独保留，避免长事实摘要挤掉真实文件 ID。成果复核阶段关闭重复证据注入，计划已完成时明确要求最终答复并收起计划和笔记工具，防止在交付后继续改写同一计划。

复核结束控制仅在计划已推进到最后交付步骤、且已读回成果全文时收起研究工具。读取中间数据文件不会结束前面的研究或分析步骤。实际文件目录由 Rust 从持久化成果表提供，缓存参数中的文件 ID 不能覆盖已保存文件名。
