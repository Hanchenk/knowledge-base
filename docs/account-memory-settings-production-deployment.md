# 个人中心记忆设置与对话页调整生产记录

当前状态：2026-10-13 已完成生产发布及真实登录只读验收。版本 `account-memory-20261013-090000`，镜像 `sha256:b98a5fe1241b56740432659013116b6adfb39047a410f217cd142e459e234cbf`，数据库 schema 17。入口：[知小汇](http://192.168.1.34:18088/app?view=bot)。

## 用户可见变化

- Bot 页头不再显示「记忆与经验」；在账号菜单的「个人中心」集中设置跨任务记忆、提取任务经验和技能提炼，并通过「管理记忆与经验」维护个人记忆、审核技能及 Wiki / CodeGraph。
- 已完成任务的对话区域不再显示「从本任务提炼技能」。技能提炼开关关闭后，浏览器和 Agent 的新候选创建由后端拒绝；已经提交的提炼继续处理，已有候选仍可审核、撤回和删除。开关不自动遍历或提炼历史任务。
- Bot 内部页头与本页导航背景透明。页头使用实际高度留出阅读间距，对话区域改为纵向布局，避免动作挤窄消息；1440px/390px长对话首尾均可完整滚动到达。普通滚动容器边界仍按正常滚动行为裁切经过边界的部分行。

## 设置与升级

新增 `bot_memory_settings.skill_capture`，默认开启以兼容原有提炼行为。旧的 enabled/capture 值保留；设置 PUT 支持部分字段，未提交的值不覆盖。开关在服务端保存成功前维持旧值，保存失败可重试，防止重复提交。新候选提交与设置修改通过同一用户设置行的事务锁串行，后台已开始的提炼及清理不因关闭而中断。

身份变化会清空管理弹窗和来源任务请求，会话失效时清除旧任务 URL。管理入口可从任何正常应用页面打开，来源任务可以跳转回 Bot。

## 验证

本地16项独立浏览器用例、后端针对测试38项（新增5项）、格式检查及针对Clippy通过。生产Linux候选全套Rust测试 `109` 项通过，0失败；运行时及其依赖沿用原生产镜像。

生产schema16备份在无外部网络的独立PostgreSQL17容器内恢复，候选应用仅共享该容器的loopback：验证16→17迁移、原业务数量/模型配置密文/记忆设置保留、部分更新、用户隔离、关闭后拒绝新提炼、既有候选审核/清理、重启幂等。旧生产二进制在schema17上启动验证通过。没有向生产数据库插入测试任务，没有创建上游验证资产。

第一次隔离验收发现PostgreSQL目录列的 `name` 类型与SQLx Any不兼容，导致升级后的第二次启动失败，生产未切换。存在性查询改为返回整数后，重新构建并完整重跑隔离验收；首次失败报告单独保留。

切换前安全门曾因Docker挂载列表的返回顺序变化而拦截，未停止生产服务。核对全部挂载字段一致后，比较改为按目标路径排序，仍保留挂载数量及所有字段的严格校验。

切换后的真实登录验收只允许GET及登录/注销：三个开关与真实设置响应匹配，管理三页签和服务状态正常，两个旧按钮消失，桌面和390px手机布局无横向溢出，页头透明，零JavaScript错误。截图隐藏身份与业务内容，验证会话注销成功。聚合证据见[验证记录](account-memory-settings-production-verification.json)。
