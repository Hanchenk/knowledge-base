# Pi 主 Agent 问答

问答默认由 `@earendil-works/pi-agent-core@0.87.0` 执行，版本与本机 Pi 项目的 Agent 包对应。依赖来自 npm 正式发布包，版本及依赖树通过 `agent-runtime/package-lock.json` 固定；本机 Pi 项目保持原样。

Rust + React 仍是业务框架。Rust 先完成当前用户权限内的混合检索和可访问历史读取，再通过标准输入向独立 Node.js 子进程传递当前企业的问答模型配置与证据。Pi SDK 负责模型推理、工具选择及跟进回答。子进程提出工具调用，Rust 执行并返回结果，直到 Pi 生成最终答案。

## 模型与启动

在页面“设置 → 问答与检索”启用并保存问答模型，继续使用已经配置的 Base URL、模型名称和 API Key。Pi 需要该服务支持流式 `/chat/completions` 以及 `tools` 函数调用。原有“测试连接”验证普通模型请求；最终工具调用兼容性需要通过实际问答验证。密钥只通过服务端子进程 stdin 传递，不放在命令行、前端、工具结果或会话元数据中。

原生部署需 Node.js 22.19+ 并执行：

```bash
npm ci --prefix agent-runtime --ignore-scripts
```

`PI_AGENT_NODE` 默认 `node`，也可指定绝对路径；`PI_AGENT_SCRIPT` 默认 `agent-runtime/agent.mjs`，从项目根目录启动 Rust。Docker 镜像包含 Node.js 与正式 SDK。

`PI_AGENT_ENABLED=true` 默认启用主 Agent；设为 `false` 使用直接 RAG 问答。问答模型未启用时保留原文检索，不启动 Agent。Agent 异常会明确报错，不伪装成成功的工具调用或回答。

## 工具

| 工具 | 行为与权限 |
| --- | --- |
| `knowledge_search` | 当前用户、租户和所选知识空间内的混合检索，分配稳定的 `[数字]` 引用 |
| `knowledge_read` | 读取授权文档的索引正文，可指定页码；每次最多 12 个片段、24,000 个字符；检查 `document.read`、空间权限和有效版本 |
| `knowledge_spaces` | 查询可查看空间；选择了空间时仅返回该空间 |
| `web_search` | 仅在该次提问开启联网且管理员策略允许时提供，返回公开检索结果和 `[W数字]` 来源 |
| `web_fetch` | 同样要求联网开启，读取公开 HTTP/HTTPS 文本页面，提取正文和标题 |

每次知识工具调用重新加载用户活跃状态、角色和 API Key 是否撤销及当前 scope。Pi 无法指定其他用户、企业或绕过所选空间。回答完成后再次校验所有知识库证据及历史依赖的权限、有效版本，才返回并持久化。撤权、更新或删除后，相关历史回答连同网页来源及工具记录一起隐藏。

工具集目前用于读取知识和公开资料；新增业务工具应在 Rust 中注册对应执行器、验证用户权限，并在 Node 的工具声明中添加 schema。外部 Agent 仍可使用原有 MCP 和 REST 接口；未提供任意 MCP 服务器动态加载、终端执行或本机文件访问工具。

## 联网与记录

### 在问答中添加文件

输入框的附件按钮支持 PDF、DOCX、XLSX、PPTX、Markdown、TXT、CSV、PNG、JPEG 和 WebP，每个文件最大 500 MB，每次提问最多 10 个。先选择具有创建和查看权限的保存空间，再选择文件；文件通过现有上传与 Worker 索引流程持久化到知识库，沿用该空间的成员查看权限。图片和扫描件仍需要视觉模型。

索引完成前禁用发送，失败会显示原因，可从问题中移除失败附件。索引完成后可填写问题，也可直接发送以总结附件。带附件的提问通过 `document_ids` 限定初次混合检索及 Pi 的知识工具范围；空泛总结问题也会获得每份附件的开头片段，Agent 可按文档 ID 和页码继续读取。服务端检查附件的租户、查看权限和有效索引版本，权限或版本失效后拒绝使用。`GET /api/documents/{id}/status` 提供相同权限校验的轻量状态查询，不加载全文片段。

问答失败保留附件以便重试，不重新上传；成功后清空本次附件选择。移除附件或开启新对话只清除问题中的选择，已上传文件继续保留在知识空间中，可在文档管理中查看和管理。每次提问结束后附件限制解除，后续问题按页面选定知识空间和授权历史检索。

页面默认选择“知识问答”，切换到“智能搜索”后启用联网，每次提问发送 `allow_web`。`AGENT_WEB_ENABLED=false` 是管理员全局禁用开关。联网会向外部搜索服务发送查询词，Agent 提示要求仅使用相关公开词、不发送企业原文；这不是自动敏感数据检测功能。

`WEB_SEARCH_URL` 留空时使用公开 Bing RSS。生产可将它设置为自有 SearXNG 的 `/search` 地址，服务需允许 `format=json`。搜索服务不可用时工具返回错误，Agent 可以说明缺少外部证据。

公开网页读取拒绝内网、本机、链路本地、云元数据及非 HTTP/HTTPS 地址；校验 DNS 返回地址并固定解析结果，逐次检查跳转，不使用系统代理。最多跟随三次跳转，响应最多 2 MB，提取正文最多 16,000 字符，超时 20 秒。搜索端点是管理员部署配置，可连接自有内网 SearXNG；Agent 不能自行替换端点。

回答 API 附带 `engine`、`web_sources`、`tool_calls`。来源包含稳定的 `citation_number` 与 `referenced` 标记；页面仅显示实际引用的来源，不重新编号，但完整证据仍保留在返回值及数据库中以校验权限。页面同时显示工具完成 / 失败状态。新增迁移 `002_agent_metadata.sql` 将这些字段写入会话元数据表；业务数据和历史与现有数据库一起持久化。工具审计只记录名称、结果和调用者，不保存检索词、完整工具参数或模型密钥。

每次最多 8 轮模型调用、16 次工具调用；Pi 内部 240 秒取消，Rust 250 秒终止子进程。单个 API 进程最多同时运行 4 个 Agent，请求过多时返回 429。超出预算或模型不支持工具调用时需缩小问题或更换兼容模型。

## 数据库现状

生产 Compose 是 PostgreSQL 17 + pgvector，使用 HNSW 向量索引和 GIN 全文索引，并用 PostgreSQL 持久化账号、权限、文档、任务、对话及 Agent 元数据。文件存入 MinIO。当前本地 `.env` 仍为 SQLite + 本地文件，向量保存在 SQLite、在应用内计算相似度。

yemast-wiki 的本地部署配置是 PostgreSQL + 独立 Qdrant + raglite。本项目使用 pgvector 将向量与业务持久化合并在 PostgreSQL 内，没有引入 Qdrant 或 raglite。此轮接入主 Agent 不迁移当前 SQLite 资料；切换数据库需另做完整迁移和目标环境验收。
